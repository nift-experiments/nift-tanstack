# Prioritized Nift/integration handoffs — no core changes made

These are candidate future tasks, not changes or commitments to the release. Reproduction starts from this private local experiment. Most problems belong to integration guidance/tooling rather than demonstrated core limitations.

| Priority | Proposal | Reproduction and impact | Suggested change | Core required? |
|---|---|---|---|---|
| P0 | Supported normal-init Start/Vite recipe | Repeat this setup without README: developer must invent sync, watcher, cache and serving boundaries. Initial implementation made several incorrect assumptions. | Ship one small tested reference adapter with native Start routes, explicit static/app ownership, commands and source map. Keep migration mode separate. | No; docs/scaffold/plugin first. |
| P1 | Reusable stage input/output contract | Initial fingerprint skipped Vite when client output was missing and omitted imported config. Current test deletes one JS artifact and proves repair. Future tool/env/config changes still need explicit force + contract updates. | Record successful outputs and declared files, environment/toolchain keys; invalidate on missing output; provide a safe force path. Do not market a hand-maintained hash list as arbitrary Vite graph correctness. | No initially; consider core stage API only after multiple integrations need the same semantics. |
| P1 | Vite dev lifecycle integration | Initial plugin handled change only, cached metadata and raced config restart against a stale native build. Add guide + metadata, then change plugin and content together to exercise it. | Standard add/change/unlink handling, reread metadata, single-flight async builds, shutdown/restart drain, explicit generated-output ignores and error overlay. | No; adapter lifecycle concern. |
| P1 | Clear managed-path versus app-route guidance | Nift @path emits relative index.html links. The first dev middleware incorrectly appended /index.html to those explicit file paths. App links use a separate root route namespace. | Add end-to-end examples/tests for page names, file URLs, assets/images/videos and cross-boundary app links. | P2 | Documentation discoverability | The official markup URL could not be retrieved through the web reader during setup, so local handover/source docs were used. This is a documented discovery failure, not proof the public URL is globally broken. | Verify canonical links/redirects and publish a short current syntax + CLI integration guide accessible to agents. | No. |

## Acceptance bar for a reusable integration

A small fixture should exercise clean-state bootstrap, no-op, one docs edit, shared-shell fan-out, app edit, missing artifact repair, guide add/remove/rename, literal @scope/template-like text, native @path file navigation, config restart, failed renderer overlay/recovery, and a relocated production artifact. Include tool/environment invalidation and a real hosting adapter before calling it turnkey.

Do not change Nift's Markdown or app compiler to address a failure in custom middleware. This experiment demonstrated no Nift core ceiling. The highest-value work is packaging the integration knowledge and reducing policy that every agent currently has to invent.
