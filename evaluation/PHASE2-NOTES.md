# Phase 2 implementation notes

- Preserved original workspace and all62-page conclusions. Public baseline copy redacts workstation path strings; original hashes retained separately.
- Both integrated models use exactly one Start/Router/React shell, identical MDX compiler/highlighter/search/runtime and two bounded SSR workers. The control also has per-document cache and publication fingerprints; Nift is not credited for generic caching available to either.
- Nift uses native `status().stringify()` and `@dep` plus tracked JSON injection for per-document payload publication. Initially assumed nonexistent `json.stringify(status())` and raw-input syntax; corrected from current docs/source. Project root moved to common repository after valid native boundary protection rejected parent paths. No core changes or weakened protections.
- Source MDX uses provider components rather than thousands of bundled imports. Official MDX function-body/runSync split is used for both SSR and client rendering. This evaluates trusted authored JavaScript and is not a design for untrusted user input or a strict no-eval CSP. This runtime tradeoff applies equally to both models and remains an adoption limitation.
- Generation is deterministic, original62guides remain unchanged, generated reference families vary service/schema/version/operation and document type. Generator code and manifest record provenance. The synthetic corpus is a production-shaped workload, not evidence of a real service API or3,000handwrittenarticles.
- First500-page hybrid prototype reused62content artifacts whereas control was fresh. Their initial times are not a matched benchmark and will not be presented as one.
- Independent reviews found concrete cache/publication recovery gaps. Nift now uses hash mode to match preserved-mtime semantics of the control. Real tests passed for one-document edits with a deliberately old timestamp, equal payloads, protected-output failure followed by successful retry, and literal `@pulse/cli` code preservation.
- Content keys are committed after publication succeeds; payload copying also compares successful source keys, so a retry cannot skip a stale existing runtime payload merely because Nift's intermediate stage already succeeded.
- Renderer/search helper implementations now participate in their stage keys. A valid serialized search artifact can be reused after an app-only rebuild, while forced full publication regenerates search.
- Bun test sets NODE_ENV=test; a first integration run exposed Vite emitting jsxDEV while the production SSR worker loaded production React. Production compilation now explicitly sets NODE_ENV=production and keys that mode. This was an integration environment defect, not an MDX or Nift core limit.
